# 成为 AS operator：自持 ASN、自有 IP 段、自己跑 BGP

来源：APNIC 政策文档（`apnic-127` ASN 管理政策）、APNIC 资格与费率页
（2026 年度费率表）、prop-128、RFC 1930 / RFC 2622 / RFC 6480（RPKI）。
汇率 AUD→CNY = 4.6671（2026-10-19）。整理时间 2026-10。

## 先说清「AS operator」指的是什么

- **AS（Autonomous System）**：一组在**同一套路由策略**下运营的 IP 前缀
- **AS operator**：对这个 AS 负责的人或机构 —— 自己持有 ASN、自己持有 IP 段、
  自己和上游 / 对端跑 BGP

它和「买台 VPS 挂个网站」的唯一区别是：**路由策略由你决定，不由你的机房决定。**

## 你到底需不需要

| 想干什么 | 需要 AS 吗 |
| --- | --- |
| 网站 / 应用跑在云上 | ❌ 不需要，云厂商的 ASN 就够 |
| 服务器要在多家运营商之间自动切换（多线） | ✅ 需要，这是最经典的理由 |
| 要一段「跟机房无关」的 IP，换机房不换 IP | ✅ 需要 PI 段 + ASN |
| 想直接和别的网络互联（IXP peering） | ✅ 需要 |
| 只是想要个好看的 whois 记录 | ❌ 不值得，一年几千块换不来什么 |

## 亚太区（含中国大陆）走 APNIC

全球五个 RIR，中国大陆属 **APNIC**。另一条路是走中国的 NIR ——
**CNNIC**（中国互联网络信息中心），它是 APNIC 体系下的国家级注册机构。

### 门槛（现行政策）

**ASN —— 门槛比很多人以为的低。**
APNIC 自 **prop-128 于 2019 年落地后，已经不再要求 multihoming**。
只要能说明「有自己的路由策略 + 需要与其他网络互联」就可以申请。
（对比：**RIPE 仍要求 multihoming**；ARIN、LACNIC 不要求。）

**IPv4 —— 真正的瓶颈。**
- 首次 LIR 分配：需证明已用掉上游一个 `/24`，或能说明立即需要 `/24`；
  并给出**一年内用到 `/23`** 的详细计划
- 小规模 multihoming 分配：正在 multihoming，或用着上游 ≥`/24` 且打算 multihoming，
  或打算 multihoming 并在 **6 个月内宣告出去**；且要**立即用掉 25%、一年内用掉 50%**

**IPv6 —— 容易得多。** 一个 `/48`（或更大）基本申请即可。

## 全流程：从 0 到路由生效

### 1. 确定主体

APNIC 面向的是**组织**，需要能签合同、能付款、能承担 whois 责任。
个人以个体经营者身份理论上有空间，但中国大陆实务上**建议直接用公司主体**
（开户、开票、后续备案都顺）。最终以 APNIC 审核为准。

### 2. 注册账号 → 申请资源

- 申请 ASN + IPv4 + IPv6（一起申请最省事）
- 提交**网络规划**：拓扑图、上游供应商合同或意向书、地址使用计划
- APNIC 评估（通常数周）→ 通过后开票 → 付款 → 资源下发

### 3. 注册路由对象（这一步最容易被漏）

拿到资源**不等于**别人会接受你的路由。要在 APNIC 的 **IRR** 里建三类对象：

| 对象 | 作用 |
| --- | --- |
| `aut-num` | 你的 AS 本身（持有者、联系人、路由策略） |
| `route` / `route6` | 你宣告的前缀，`origin` 指向你的 ASN |
| `mntner` | 维护者对象，管谁能改这些记录 |

同时建 **RPKI ROA**（Route Origin Authorization）。
现在主流运营商都做 RPKI 校验 —— **没有 ROA 的前缀会被判 Invalid 直接丢弃**，
典型症状就是你「宣告了但全世界看不到」。

### 4. 配 BGP

- 软件路由：**BIRD 2** 或 **FRR**，跑在 Linux 上，1 核 1G 就够
- 至少一个上游 transit 愿意接受你的宣告 —— **这是最关键的外部依赖**
- 建议两个上游，否则体现不出 AS 的意义（单上游直接拿上游的段更省事）

### 5. 登记 PeeringDB

建 AS 记录、填上下游、填 IXP 连接。**潜在对端靠它找你**，没有基本等于不可见。

### 6. （可选）接入 IXP

在交换中心买端口，和其他 AS 做 settlement-free peering。
亚太常见：HKIX、JPIX、Equinix 各地。

## 中国大陆的特殊约束

1. **跨境宣告**：在大陆本地宣告自己的段，需要上游运营商接受并配置。
   现实中不少人把 `/24` 从**境外 POP**（香港 / 日本 / 新加坡）宣告，
   规避国内路由策略的复杂度 —— 代价是**国内访问会绕道境外**，延迟变差。
2. **经营许可**：仅自己使用（自己的服务器用自己的段）通常不涉及电信业务许可；
   但**向他人提供接入服务**属于「**互联网接入服务业务（B14）**」，
   属第一类增值电信业务，需要相应的**增值电信业务经营许可证**。
   各省通信管理局口径有差异 —— 真要做对外服务，先问属地通管局，别照网上教程办。
3. **备案**：用自有 IP 段在国内放网站，仍受 ICP 备案约束。
   **IP 归属变了要变更接入商和备案信息**，不是自动继承。
4. 🔴 **不要碰**：宣告不属于自己的前缀（route hijack）是互联网层面的重罪，
   会被 IRR / RPKI 和上游 prefix-filter 拦住并留下证据；
   用「IP 换国家」规避地区限制则违反多数平台条款。

## 更省钱的替代方案

| 你的需求 | 替代做法 | 成本 |
| --- | --- | --- |
| 换机房不换 IP | 让上游出 **PI 段的 LOA**（Letter of Authorization），或选支持 BYOIP 的云 | 低 |
| 多线自动切换 | DNS 智能解析 / 云厂商自带的多线 BGP | 很低 |
| 只要 IPv6 | 直接申请 APNIC `/48`（但年费仍是同一个 base fee，单买不划算） | 中 |
| 纯学习 BGP | **别买 ASN**，用私有 AS 号 `64512–65534`（2 字节）或 `4200000000–4294967294`（4 字节）搭实验环境 | 零 |

🔴 **转售商的坑**：市面上有「AUD 125–200/年 代办 ASN + IPv6」的服务。
问题是 **ASN 挂在转售商的会员账号下，你不是资源持有人**。
转售商跑路或欠费，你的段跟着没。真要长期用，自己开 APNIC 账号。

## 决策表

| 你的情况 | 建议 |
| --- | --- |
| 个人、想学 BGP、没有真实多线需求 | ❌ 别买。私有 ASN + 两台 VPS 做实验就够 |
| 有公司、有跨境业务、需要固定 IP 段 | ✅ 走 APNIC，预算 **¥6,000–9,000 / 年** |
| 只是想让服务器 IP 不变 | ⚠️ 先问机房能不能 BYOIP 或给 PI 段，通常更便宜 |
| 在大陆要给第三方提供接入 | ✅ ASN **和** 增值电信牌照都要，缺一不可 |
